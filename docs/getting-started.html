Getting started

Synector is a single Windows executable with two tiers: a tray daemon that owns rules and state, and a GUI that edits them. Install it, leave the daemon running, and close the window whenever you like.

Requirements

Windows 10 or Windows 11 on x64. The setup and portable builds include everything the application needs at runtime. Rust 1.95 or newer is only required to build from source.

Install

  • Setup: Synector-Setup-<version>-Windows-x64.exe from the latest release. It installs into Program Files, adds a Start Menu shortcut, registers App Paths and includes an uninstaller.
  • Portable: Synector-v<version>-Windows-x64.zip. Extract it anywhere and run Synector.exe.
  • PowerShell: irm https://raw.githubusercontent.com/psyattack/Synector/main/installer/install.ps1 | iex. The script downloads the latest release, verifies SHA-256 and installs it.

Every release also publishes SHA256SUMS.txt. Compare it with Get-FileHash -Algorithm SHA256 when you verify a download by hand.

First launch

Synector starts elevated by default, because kernel ETW process tracing, input into elevated windows and Task Scheduler autostart need administrator rights. Pass --no-elevate when you do not want that.

The daemon starts first and shows a tray icon. The window is a separate controlling client: closing it does not stop rules, counters or monitoring. On a first run the app adopts the Windows interface language, Russian for Russian Windows and English for everything else, and keeps that choice. The palette can follow the Windows light or dark setting, or stay on an explicit choice.

Your first rule

  1. 01

    Open the rule builder

    Press NEW RULE in the header. The rules list is the only page in the app; the builder opens over it.

  2. 02

    Pick a trigger

    Choose Global Hotkey, press RECORD and press a combination such as CTRL+ALT+H.

  3. 03

    Add an action

    Add a Notification action, give it a title and a message, then save the rule.

  4. 04

    Test it

    The rule runs from the next key press, whether the window is open, minimized or closed. Use TEST RUN in the rule details to check the action pipeline once.

Prefer JSON? The same rule is a plain file. Create rule.json, then run cmd /c "Synector.exe --rules-apply rule.json". The full format, quotas and validation rules are in Rule authoring. 
{
  "id": "rule_hello",
  "name": "Hello from Synector",
  "trigger": { "$trigger_type": "hotkey", "key_combination": "CTRL+ALT+H" },
  "actions": [
    { "$action_type": "notification", "title": "Synector", "message": "The rule works." }
  ]
}

Find anything

The header holds one search field. Start typing to search rules, settings, the activity log, actions, triggers, conditions and overlay or macro presets. Results are grouped with counts; choosing a group opens that surface with the query already in place.

The chart glyph opens the analytics dialog and the gear glyph opens settings. Settings is one scrolling column of blocks with its own search field, and every switch or picker saves as you change it.

Change the appearance

Settings > Appearance has three independent controls: the palette (dark, light or follow Windows), the interface skin (Modern or Classic) and the accent colour. Changing one never changes the others. Modern is the default: rounded, layered surfaces and a sans-serif voice. Classic keeps the original square chrome, hairlines and mono labels.

Files and backups

All user files live in %LOCALAPPDATA%\Synector\. Set SYNECTOR_CONFIG_DIR to relocate the whole directory for a portable or isolated run.

File or folderContents
settings.jsonWindow geometry, tray visibility, masking, disk logging, language, palette, skin, accent, Windows theme sync and update preferences
rules.jsonRule definitions, with runtime counters written zeroed
library.jsonOverlay and macro presets
runtime.jsonPer-rule execution counters, last-run timestamps and quota-window anchors
logs\Daily diagnostic logs with seven-day retention
While the daemon is running it is the only writer. Stop Synector before copying or editing the files by hand. A section that fails to parse is preserved as <name>.corrupt-<timestamp> instead of being overwritten.
