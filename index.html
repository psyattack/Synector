The GUI is optional.Интерфейс не обязателен.

A tray daemon owns every rule, trigger and counter. The window is an editor you can close at any time. Фоновый демон в трее ведёт правила, триггеры и счётчики. Окно лишь редактор, который можно закрыть в любой момент.

Two processes. One owner of state.Два процесса. Один владелец состояния.

The daemon starts with Windows and owns every rule and counter. The GUI edits a draft and sends only changed sections over a named pipe. Демон стартует вместе с Windows и владеет правилами и счётчиками. Интерфейс редактирует черновик и отправляет по именованному каналу только изменённые секции.

Analytics belongs to the daemon. The GUI asks for a snapshot only while the analytics dialog is open. There is no telemetry; network use is limited to the local webhook, rule webhooks and the GitHub update check. Аналитика принадлежит демону. Интерфейс запрашивает снимок только пока открыт диалог аналитики. Телеметрии нет: сеть используется только локальным вебхуком, вебхуками из правил и проверкой обновлений на GitHub.

Built as a supervisor, not a script runner.Создан как супервизор, а не запуск скриптов.

Rules, overlays, macros and companion processes share one engine, one schema and one daemon. Правила, оверлеи, макросы и процессы-спутники работают на одном движке, одной схеме и одном демоне.

Pipelines with real control flowКонвейеры с настоящей логикой

RulesПравила

Waits, inline checks, If/Else branches and toggles run in order. Cooldowns and lifetime or periodic quotas stop accidental loops. One rule can call or stop another and observe its pipeline. Ожидания, проверки, ветвления If/Else и переключатели выполняются по порядку. Кулдауны и лимиты запусков останавливают случайные циклы. Одно правило может вызвать или остановить другое и наблюдать за его конвейером. 

{
  "trigger": { "$trigger_type": "process", "process_name": "game.exe" },
  "actions": [
    { "$action_type": "start_process", "file_path": "recorder.exe" },
    { "$action_type": "wait", "seconds": 2.0 },
    { "$action_type": "notification", "title": "Profile active",
      "message": "Recorder attached" }
  ]
}

Events where Windows has them. Polling where it does not.События там, где Windows их даёт. Опрос там, где их нет.

No pretending every source is event-driven. Kernel ETW covers process lifecycles when elevated. Polled sources use adaptive intervals, not fixed timers. Никаких заявлений, что все источники событийные. При повышенных правах жизненный цикл процессов отслеживается через kernel ETW. Опрашиваемые источники используют адаптивные интервалы, а не фиксированные таймеры.

InterfaceИнтерфейс

Two skins. One engine.Два скина. Один движок.

Modern is the default generation: rounded, layered surfaces and a quieter type voice. Classic keeps the original studio chrome. Palette and skin are independent, so either skin works in dark, light or a Windows-followed theme. Modern теперь основная тема: округлые слоистые поверхности и более спокойная типографика. Classic сохраняет исходный студийный хром. Палитра и скин независимы, поэтому любой скин работает с тёмной, светлой или системной темой Windows.
